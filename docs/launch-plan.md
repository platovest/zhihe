# 知合：本地内测与上线准备

## 交付边界

本轮目标是可在本地运行、可被真实用户检查的一节免费课，以及可由运营人员处理的未来课程意向。不自动公开部署、不接收付款。将代码推到 GitHub 不会使本地数据库成为线上服务。

产品假设、角色和继续条件见 [product-brief.md](./product-brief.md)。本文件中的用户招募、人工联系和收费前事项是未来运营操作，不能在交付报告中写成已经执行。

## 开始第一场内测前

1. 按仓库 README 的本地启动步骤运行，并确认当前服务、数据目录及数据库是本地的。仅向用户演示本机或其授权的本地环境；不要临时开公网隧道。
2. 先用测试地址验证课程、登记、重复提交、撤回、运营查看和导出。重启服务后再查一次测试记录，验证持久化；清除测试记录后才统计正式数据。
3. 确认界面清楚写明一节可学、其余为计划、¥199 仅意向且不扣款。未实现自动邮件就不能承诺自动提醒；未完成独立专业审阅就不能使用背书文案。
4. 运营人员必须有可实际到达的联系渠道。在主持式本地测试中，可当面提供负责人的姓名和联系方式；参与者须知道如何撤回或要求删除。没有真实负责人和联系渠道时，只使用虚构测试邮箱，不收集真实个人信息。
5. 选择最少必要的记录方式：正式名单与匿名观察分开保管，文件不进入 Git。主持式测试默认不录音、不录屏、不记录个人亲密经历；额外研究用途另行说明并取得同意。

具体程序命令以 [README](../README.md) 与实际运营脚本的帮助输出为准；执行删除、恢复等操作前确认当前数据目录，先在隔离测试数据上演练。

## 20 人主持式内测

由产品负责人招募自愿的成年中文用户，先做 5 人观察，再做 15 人。尽量不全部来自开发团队或密切亲友；便利样本的偏差必须在结论中记录。招募和联络由运营人员实际执行，不由本轮代理自动外发。

每人约 15–20 分钟，按同一脚本：

1. 告知这是免费内测，可以随时停止，不需要透露亲密经历；邮箱登记完全可选。
2. 请对方从首页独立找到并完成课程。主持人不帮选答案，只记录卡住的界面和是否需要帮助。
3. 问：“刚才最有用和最不清楚的分别是什么？”“如果对方中途改变主意，你会怎么处理？”
4. 给一个新的虚构场景，请其口述一句回应；只记录是否体现尊重边界，不保存原话或原始练习输入。
5. 展示相同的未来七课 ¥199 说明，让其自主决定是否登记，再问：“你认为登记后会发生什么？”不先问“你愿意买吧”。
6. 问：“现在结束体验，你会带走什么？”“有什么会让你不愿继续用？”避免把礼貌夸赞当需求证据。

每人用 P01–P20 编号。观察表只记录：是否独立完成、是否理解可以停止、是否迁移到新例子、是否见到价格、是否登记、主要阻塞类别、是否中途退出。邮箱不写入观察表；不逐人连接行为与联系方式。

5 人阶段发现严重理解问题就先修复，再重新开始正式批次并记录版本，避免把不同版本结果混算。20 人结果按固定门槛评估，不为达标事后改分母。

## 运营处理闭环

每个测试日结束，由一名指定负责人执行：

1. 查看当日新增意向及汇总事件。将同一邮箱的重复登记视为一人意向；点击数和事件数不是独立访客数。
2. 有需要时导出最小字段，保存在受保护的本地目录，不上传 GitHub、共享聊天或第三方分析工具。导出只为本轮已说明的用途。
3. 只对明确同意联系的用户进行人工跟进。实际发出联系后再记录时间和状态；生成草稿或“标记已联系”不是送达证据。无收件人验证时，地址可能是误填，不能当有效潜客总量。
4. 联系内容应重申课程仍在验证、没有订单和扣款；提供便捷的停止联系方式。撤回后先删除对应意向或执行系统提供的撤回流程，再处理本地导出副本。
5. 定期清理不再需要的数据，至少每个测试日检查到期记录。保留期限必须和界面及实际实现一致；若仅有手动清理，不能宣称定时任务持续运行。电脑关闭期间不会执行本地作业。
6. 整理匿名结果和阻塞点，按产品定义决定继续、改课或停止。保留版本、样本量和判定依据，不保留多余个人资料。

人工联系示例（仅供负责人在获准后使用，本轮未发送）：

> 你好，你此前在知合免费内测中自愿登记了未来课程开放通知。现在课程已开放，具体已交付内容与价格请以正式说明为准。此前登记不是订单，也没有扣款。是否了解或购买完全自愿；如需删除登记，可使用原撤回凭证，或回复此邮件联系我处理。

仅在课程真实开放且用户授权外发后使用此模板，不得提前发送。体验访谈需另行取得同意，不复用课程通知同意。

## 统计口径

产品事件只允许预定义的流程节点，例如进入页面、开始课程、完成课程、查看价格和登记成功。不把练习答案、情境选择、自由文本、邮箱、完整 URL 查询参数或跨站标识作为统计属性。

如果实现仅聚合事件计数，就明确报告“次数”，不要报告独立用户转化率。20 人实验的完成率和意向率来自主持记录；匿名事件用于发现页面流程异常，两者不能直接逐人关联。用户关闭统计也应能学习和登记；不以敏感主题画像代替研究。

## 本地交付验收

- 完整免费课能走到反馈与可带走的练习卡，离开或重新开始不会强制登记。
- 用真实本地数据库验证合法写入、重复登记、坏输入拒绝，以及重启后数据存在；模拟数据库测试不能替代这些证据。
- 运营查看、导出、联系状态、撤回与清理的实际能力与 README 一致；没有实现的项目明确列为限制。
- 删除后再查询确认不存在；备份恢复在隔离路径验证，不能覆盖活动数据库。恢复旧备份后必须重新应用已经发生的删除请求。
- 手机窄屏、键盘焦点、弹窗关闭、网络失败提示及重试经过实际检查；编译通过不能代替交互验收。
- Git 忽略真实数据库、联系名单、导出和运行日志。提交前检查暂存内容，只有代码和说明同步到用户指定仓库。

## 公开免费内测前仍需决定

用户明确选择部署位置和可访问范围；配置真实运营负责人及联系渠道；完成独立内容审阅；用部署环境验证数据保存、删除、备份、服务重启、访问控制和故障处理。若开放互联网，还需重新设计可靠的限流、防滥用、日志和邮件地址验证；本机隔离或内存限流不能等同公网抗滥用能力。

## 正式收费前仍需完成

先获得足够的首课学习证据，再完成七课实际交付与内容授权；明确经营主体、服务地区、支持联系、课程范围、交付时间、退款规则和服务条款；向实际支付服务商提交真实内容类型，取得接入许可；实现付款确认、幂等订单、购买权益、退款与对账，并在测试环境覆盖失败和重复回调。

公开收费前应由对应地区的专业人士确认经营、消费者权益与隐私要求。不直接套用其他地区条款，也不把“有教育目的”“18 岁确认”或本地测试通过视为经营许可。

尚无付费交易，本轮不能宣称收入、复购、退款率、客户获取成本、产品市场匹配或商业闭环。当前可验证的是课程可用性、初步学习理解和自报意向。
