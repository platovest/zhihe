# 知合：免费内测产品定义

本文件是产品决策与验收目标，不是用户测试结果或上线证明。实际完成情况以代码、测试记录及人工验收为准。

## 根目标

让成年中文用户在一节非露骨的沟通教育课里，学会表达一个具体边界、听见对方的不确定，并能在对方改变主意时停止。先验证是否有实际帮助，再验证是否有人愿意了解未来课程；本轮不收款。

最小闭环：看懂价值 → 免费学完一课 → 完成情境练习并获得解释 → 带走练习卡 → 自愿登记未来课程意向 → 运营人员查看并处理 → 根据访谈与必要的汇总数据决定下一轮。

GitHub 同步是代码交付；本地可用是开发验收；真实内测通过是用户价值证据。三者都不等于公开上线或商业闭环。

## 用户、问题与范围

首批面向自愿参加的 18 岁以上中文用户：想更自然地表达意愿与边界，但不希望留下亲密经历记录的人。是否处于伴侣关系不是参与条件，不收集性经历、性取向、健康诊断或伴侣姓名。

任务是“给我一个可以尝试的表达方式”，不是承诺改善关系、治疗问题或评估某个人。情境练习使用虚构例子；任何时刻都可跳过或退出。

本轮交付一节完整免费课和练习卡。其余六节只作为明确标注的规划内容。¥199 是未来七课方案的价格实验，不是当前商品、订单、预付款或名额保证；不显示虚构销量、倒计时、限量席位、专家背书和退款承诺。

## 内容依据与证据边界

- WHO 将积极、尊重、免于胁迫的关系纳入性健康讨论，因此本产品围绕尊重和自主表达设计，不以刺激内容为卖点。[WHO：Sexual health](https://www.who.int/en/health-topics/sexual-health)
- Planned Parenthood 的同意教育强调自愿、可改变、知情与具体；本产品将这些原则用于虚构的日常沟通情境，具体中文例句及练习是团队原创设计。[Planned Parenthood：Sexual consent](https://www.plannedparenthood.org/learn/relationships/sexual-consent)
- 中国《个人信息保护法》第六、十五、十七、十九条分别涉及最小必要收集、撤回同意、告知和必要的最短保存期。本产品采用少收集、清楚告知、提供撤回和删除流程的设计；这不是完整法律适用结论，经营地区确定后仍须针对实际运营核查。[市场监管总局转载法律全文](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)

这些资料支持教育原则和数据设计，不能证明本课程具有临床效果，也不能推出中文市场规模、付费意愿或产品优于竞品。内容目前没有完成独立专业审阅，不得使用“专家审定”“临床验证”等表述。

## 本轮成功条件

| 假设 | 观察方式 | 下一轮继续探索门槛 |
| --- | --- | --- |
| 一课能被独立完成 | 20 名用户在主持人不提示答案的情况下体验，记录是否完成及阻塞点 | 至少 12/20 独立完成 |
| 核心原则被理解 | 课后用自己的话解释“对方改主意时怎么办”，不考原句记忆 | 至少 14/20 明确说出可以停止、不需要说服 |
| 能迁移到新情境 | 用另一段虚构对话，写出或口述一句尊重边界的回应 | 至少 12/20 达成；只记通过与否，不保留原答案 |
| 未来方案值得继续调查 | 每人都看到同样的 ¥199 与“尚未交付、不扣款”说明后，自行选择是否登记 | 至少 6/20 自愿登记，且登记者均理解不是已购买 |

上述门槛全部是本项目预先约定的实验假设，不是行业基准。样本小且为便利招募，不做市场代表性推断，不将意向率称为购买转化率。所有分母固定为 20 名开始测试者，退出和未完成计入未通过；不得只报告完成者。

若学习门槛通过、意向未通过，先访谈价格和课程价值，不直接降价或增加大量功能。若学习或迁移未通过，修改首课后重新招募一小批验证。出现诱导同意、泄露个人信息、用户无法退出或“登记即付款”的误解，暂停相关流程并先修复；后者应重新检查所有商业文案。

## 团队责任

由项目经理统筹，下列七种职责由协作代理分工承担，不代表聘请了七名独立人类专家。

| 角色 | 本轮交付与责任 |
| --- | --- |
| 商业分析调研员 | 核实一手资料，提出可证伪假设，访谈后区分事实与解释 |
| 产品经理 | 一课到底的用户路径、价格实验和逐项验收标准 |
| 视觉与交互设计师 | 清楚的阅读层级、可退出交互、手机和键盘使用体验 |
| 研发经理 | 本地稳定运行、持久化、输入校验和最小运营工具 |
| 测试经理 | 真实数据存储与重启、导出与删除、课程主路径与失败路径证据 |
| AI 专家顾问 | 辅助生成虚构例子、可读性检查和测试用例；复核输出边界 |
| 商业化专家 | 20 人内测、手动跟进、真实意向计数和收费前条件核对 |

项目经理按“根目标 → 假设 → 最小实施 → 证据 → 下一步”维护决策，每次扩大范围必须说明与根目标的关系。工程采用最少改动、明确假设、可验证完成标准；不为可能的将来先做账户、社区、订阅、复杂 CMS 或智能推荐。

## AI 的使用

运行时课程采用固定内容和可检查的规则反馈，不根据用户亲密经历生成建议。本轮无需调用模型 API。AI 可以在制作阶段辅助草稿和测试，但人类内容审核责任不能交给模型。真实邮箱、访谈内容、练习答案不输入外部模型；不做诊疗、人格推断、伴侣风险评分或自动个性化价格。

## 不在本轮范围

真人露骨内容、用户上传、医疗咨询、即时聊天、付款、付费权益、退款系统、自动营销邮件和公开部署。下一轮是否开展，必须由真实内测证据与实际运营能力决定。
