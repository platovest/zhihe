## 真实支付接入验收矩阵

选定服务商后，用其官方 sandbox/测试环境验证以下场景。本文件不声称服务商会提供通用的“合格证”；通过指团队按官方机制取得可复查记录。

| 场景 | live 前检查 |
| --- | --- |
| 回调身份 | 用官方机制验证原始请求和签名，拒绝缺失、篡改、过期或不属于本商户/环境的事件；密钥不进入浏览器 |
| 订单与金额 | 核验商户、商品、金额、币种及交易对应关系；前端成功跳转不是付款依据 |
| 幂等与顺序 | 重复创建、重复事件、重试和乱序只产生一次有效动作；保存事件处理与重试结果 |
| 异步状态 | 成功、拒付、处理中、超时和取消按官方状态处理，晚到事件与权限保持一致 |
| 对账 | 本地订单与服务商交易、费用、退款逐笔匹配；差异有可操作告警和人工处理记录 |
| 退款 | 申请、受理、处理中、失败和成功均验证；请求发出不等于钱已退；撤权策略与真实退款状态一致 |
| 环境隔离 | sandbox 与 live 账号、密钥、回调、数据分离；测试卡和事件仅用于官方支持的测试环境 |
| 上线恢复 | 事件可安全重放、数据库可恢复、失败可回滚；不会因回滚重复扣款或漏掉退款 |

核查来源示例仅说明技术机制，不代表已选择或接入该服务商：Stripe 要求使用原始请求验证 webhook 签名，并说明事件可能重复。[官方 webhook 文档](https://docs.stripe.com/webhooks) 测试和退款文档分别说明测试方式与退款状态，自制成功按钮不能替代这些验证。[官方 testing](https://docs.stripe.com/testing)、[官方 refunds](https://docs.stripe.com/refunds)
